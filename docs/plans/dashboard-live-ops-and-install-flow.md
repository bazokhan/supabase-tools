# Dashboard Live Ops and Install Flow

## Goal

Address four UX gaps in one coherent dashboard pass:

1. Fix spacing/layout quality of newly added Plugin/Services cards.
2. Let dashboard plugin actions optionally run package installation (not only config edits).
3. Reduce/manual refresh by making dashboard data refresh automatically after outputs/changes.
4. Add process lifecycle controls in dashboard (start/stop long-running commands, docs start/stop, watch, migration-studio).

## Problems to Solve

1. New card spacing is visually inconsistent with existing panel rhythm.
2. `Add plugin` updates config only; users still must leave dashboard and run `npm install`.
3. Many pages rely on manual refresh because there is no central invalidation/event model.
4. Commands page starts tasks but cannot reliably stop server-like processes or represent process ownership/state across routes.

## Proposed Solution

### A) UI spacing and visual consistency

- Tune Plugin/Services grid/card spacing to align with existing token scale and panel density.
- Ensure button rows and badges wrap consistently on mobile.
- Keep changes confined to dashboard style tokens/classes used by new pages.

### B) Plugin install from dashboard

- Extend `POST /api/plugins` to support optional install behavior:
  - `action: "add"` plus `install: true`
- Server executes package manager install command for package-name plugins:
  - Default: `npm install <plugin>`
  - Reject install for filesystem-path plugins with clear message.
- Response includes install output summary and success/failure status.
- Preserve existing no-install behavior for users who only want config changes.

### C) Live update model (no manual refresh)

- Add server-side event bus in dashboard command:
  - Emit events on plugin config change, command start/exit, docs lifecycle actions, and file-generation actions triggered from dashboard.
- Add client-wide lightweight subscription hook (SSE) in ui-web:
  - On event, refresh relevant hooks:
    - commands
    - plugins
    - services
    - atlas/config when generated by runner actions.
- Keep fallback polling, but reduce interval and rely primarily on events for quick updates.

### D) Process lifecycle controls

- Expand dashboard run API to support args for relevant commands:
  - `docs swagger|redoc|schemaspy|all|stop`
  - `watch` and plugin servers as long-running.
- Add process registry with command keys and stop handlers:
  - Track spawned process metadata
  - Add `POST /api/run/stop` endpoint
  - Stop by command key; safe no-op if not running.
- Runner page:
  - Show running-state badges consistently
  - Render `Stop` for long-running tasks
  - Show docs quick presets (`start all`, `stop`) as command variants.

## Implementation Steps

1. Core dashboard backend
   - `packages/core/src/commands/dashboard.ts`
   - Add install-enabled plugin action branch.
   - Add central event emitter + SSE event payloads.
   - Add stop endpoint and robust process registry updates.
   - Add command variants/arg support for docs and other long-running tasks.

2. UI hooks/state
   - `packages/ui-web/src/dashboard/hooks/useCommands.ts`
   - `packages/ui-web/src/dashboard/hooks/usePlugins.ts`
   - `packages/ui-web/src/dashboard/hooks/useServices.ts`
   - Add shared SSE subscription hook (new file) and wire invalidation callbacks.

3. Runner page UX
   - `packages/ui-web/src/dashboard/pages/Runner.tsx`
   - Add stop/start controls for long-running processes.
   - Add docs variants and status-aware actions.

4. Plugins page UX
   - `packages/ui-web/src/dashboard/pages/Plugins.tsx`
   - Add “Add + Install” action and output feedback.

5. Spacing polish
   - `packages/ui-web/src/styles/tokens.css`
   - Normalize card/grid spacing and responsive behavior for new pages.

6. Tests
   - Extend `testing-scripts/tests/11-dashboard-first-run.ts`:
     - plugin add+install path (mockable/guarded)
     - runner stop lifecycle
     - event-driven refresh checks (API-level assertions).

7. Docs/metadata
   - Update `AGENTS.md` and `CLAUDE.md` dashboard API routes and page behavior.
   - Add/adjust changeset if behavior scope grows beyond existing entry.

## Validation

1. `npm run build -w packages/core`
2. `npm run build -w packages/ui-web`
3. `npm run test:scripts`
4. Manual:
   - Add plugin with install from dashboard and see immediate status update.
   - Start docs from runner, verify reachable links update automatically.
   - Stop docs/watch/server commands from runner without page refresh.
   - Confirm Plugin/Services card spacing and mobile layout.

## Risks and Mitigations

1. Installing packages from dashboard can fail due to permissions/network.
   - Return actionable stderr summary and keep config state explicit.
2. Process stop behavior may differ on Windows shells.
   - Track child process handles directly; avoid shell wrappers where possible.
3. Event over-refresh can cause noisy network updates.
   - Debounce invalidation and keep event payloads typed by scope.

## Out of Scope

1. Full task orchestration/history across dashboard restarts.
2. Background daemon for process persistence beyond dashboard process lifetime.
